## What remains / needs testing

1. **Rotate**: Second fix applied. Root cause: SolidJS component body runs once, so when `replaceDocument` swapped the handle, `DocumentViewer`'s internal `renderedPages` Map and `renderCache` ref still held old data. Added `createEffect` watching `props.handle` that clears local state, repoints cache, re-triggers thumbnails (`loadAll`) and full-page renders (`queueVisiblePages`). Needs manual testing.
2. **Crop**: CropOverlay is wired end-to-end but not yet tested. Click crop icon on full-size page → draw rectangle → "Apply crop" → should crop the page.
3. **PagePreview overlay**: PagePreview uses DocumentViewer which now has actions. Rotate/crop should work in the preview modal too.
4. **Edge cases to test**:
   - Rotate on view page, split page, reorder page thumbnails
   - Rotate in PagePreview modal
   - Crop coordinate mapping (PDF uses bottom-left origin)
   - Multiple rotations in sequence
   - Rotate + undo (no undo implemented yet)

## Key architectural decisions

- **`replaceDocument()`**: atomic swap pattern — load new doc first, update signal, then clean up old. Prevents viewer unmount flash.
- **`PageAction` system**: extensible via `usePageActions()` hook. New operations (greyscale, single-page compress) just add entries to the returned array.
- **`render-cache.ts`**: extracted to break circular dependency between PdfContext and DocumentViewer.
- **`cropBox` coordinates**: CropOverlay works in fractional [0,1] screen space, converts to PDF points with Y-flip on confirm.
